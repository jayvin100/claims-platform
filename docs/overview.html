Architecture

One Angular app, one ASP.NET Core API with three modules (a modular monolith, ADR-0001), Postgres and Kafka. Notifications and Reporting never read the Claims tables; they only know what the events tell them.

REST: a user waits for the answer Kafka: nobody waitsDead-letter topic (D90) Database: "1 tx" is one transaction for the Claim change and its outbox row

Why REST

"Every command and query is a REST call, because a user is waiting for the answer." The Claimant needs an immediate answer (validation errors, a Claim Number). ADR-0003 D10

Why Kafka

"Each change also produces a domain event, which reaches Kafka through an outbox (ADR-0004), and nobody waits on what happens next." Emails and the Exposure and Workload read model are built from events, so Kafka does real work rather than being decorative. ADR-0003 ADR-0004 ADR-0005

Three questions the panel is likely to ask, answered as flowcharts. Each node shows the file it lives in. The order in the first tree is the order the code runs: authentication and authorisation middleware (src/Claims.Api/Program.cs), then the controller's model validation, then ActOnClaim, then the Claim's method, then the save.

1. Which response does a request get?

Steps 4 to 8 apply to actions on an existing Claim. Step 5 runs only in SetReserve, RequestInfo, Approve, Reject and Settle: PickUp checks the status alone, so picking up a Claim another Officer holds gets step 6's 409, not 403. Inside step 6, Request info checks for an already open Info Request before the status (also 409). Order checked against src/Claims.Api/Claims/Claim.cs.

3. A consumer receives a message: what happens?

This tree follows D90, Jay's override of D74 and D79, and matches the README's consumer tree. ReadEvent checks the header, the value, a known type and JSON that fits it (required, non-null fields) before the database, because the event id comes from the JSON; only then does ProcessAsync check for a duplicate. Poison is never recorded as processed, so a replayed copy counts as new. Before D90, Reporting stalled its partition on a bad message and Notifications logged it and moved on. Notifications' ignored types (ReserveSet, InfoProvided) are handled: recorded as processed with no email (D68).
